# 教学代码详细注释质量门槛

本门槛适用于 FFTCN 项目从里程碑 3 起的所有教学 Markdown 完整代码章节及其独立参考答案，包括同一里程碑中的内部步骤文件。未通过本清单，不得把对应练习交付为“等待用户练习”。

## 必须逐项满足

1. **接口语义**：函数 docstring 必须逐一说明每个输入参数是什么、形状或类型、由运行链中的哪个上游函数创建并传入；同时说明返回值交给哪个下游使用。只写一句函数概述不算通过。
2. **紧密代码片段**：每一行或每个最多 2–4 行的紧密片段前，都说明“做什么”和“为什么算法需要这样做”；不得只把赋值、循环或 API 名称换成中文复述。
3. **变量来源与职责**：首次出现的每个中间变量都必须解释数据来源、当前语义和后续用途。累加器、计数器、游标和默认初值必须说明为什么需要独立保存，例如 `position_count = 0` 是 epoch 平均损失公式的分母累计量，不只是“定义一个变量”。
4. **形状与轴**：每次 `reshape`、`flatten`、`permute`、`argmax`、按轴求和或拼接，都先解释模型/算法意图与轴的实际含义，再说明 NumPy/PyTorch API 约束。
5. **公式映射**：指标或算法公式必须对应到代码变量，说明分子、分母以及边界分支。例如 `TP/(TP+FP)` 要对应 `true_positive/predicted_count`。
6. **框架状态**：`train/eval`、`no_grad`、设备移动、dtype 转换和 CPU/NumPy 转换必须解释其行为影响。
7. **数据类型转换**：`int()`、`float()`、`tolist()`、`dict()` 等转换必须说明为何需要，以及服务于哪个下游接口。
8. **返回结果**：返回前说明每个字段或返回对象将被下游怎样使用。
9. **核心与加固分离**：主代码只保留算法正确性必需检查；额外生产防御放入“工程加固（选读）”，但不能用“保持简洁”为由删除核心数据流注释。
10. **三份接口同步**：正式练习骨架、教程第 4 节与 `reference_solution.py` 必须具有相同的练习函数和调用关系；教程与参考答案的算法、接口和注释粒度保持一致。修改任一处后必须重新检查另外两处。

## 交付前人工审读

Codex 必须把当前教程的完整代码章节当作独立材料从头读一遍，并能对每个非平凡语句回答：

- 这一行输入是什么？
- 输出是什么，形状或类型怎样变化？
- 为什么算法需要这一步？
- 该变量稍后在哪一行使用；如果删掉会失去哪部分信息？
- 初学者最可能误解什么？

只通过语法测试、单元测试或“注释行数统计”不代表通过本质量门槛；这些检查不能判断注释是否真正解释了代码。
