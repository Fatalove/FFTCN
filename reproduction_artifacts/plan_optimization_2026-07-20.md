# REPRODUCTION_PLAN.md 结构解析与优化报告

## 1. 结论

旧文件的问题不是单纯篇幅大，而是把五类不同权限的信息混在同一个“唯一执行主线”中：

1. 现行强制规范；
2. 当前里程碑状态；
3. 稳定数据/模型契约；
4. 已完成和未开始里程碑的详细教学手册；
5. 含旧状态、旧命令和旧“下一步”的实验历史。

后两类约占旧文件约 80%。它们虽然有追溯价值，却不应在每次继续项目时与现行约束竞争注意力。

## 3. 已确认的失效或冲突指令

### 3.1 多个“当前入口”互相竞争

- 旧状态表与文末入口要求继续 9B；
- 里程碑 9 的历史日志仍写着下一次进入里程碑 10；
- 已废止的 9B.1 日志还保留 consumer-first 顺序。

模型读取同一权威文件时可能错误选择离当前位置更近或措辞更强的旧入口。

### 3.2 验收单位冲突

- 现行规则要求整个里程碑统一验收；
- 多条历史日志仍要求“实现一个函数 → 跑一个测试 → 申请检查 → 再做下一函数”；
- 内部步骤曾经使用 9B.1–9B.6 编号，外观上近似独立里程碑。

新文件在前部显式定义：里程碑是唯一状态和正式验收单位；内部步骤与函数仅用于实现顺序和行为自测。

### 3.3 已推翻规则仍保留权威外观

旧日志先把 `bn/relu` 与 `batch_norm/activation` 的内部命名差异判为阻塞，后续又确认这是过度约束。两种相反结论同时存在时，容易重新执行已推翻的规则。

新文件只保留最终规则：测试可观察行为；内部命名只有影响公开 API、算法或 checkpoint 兼容性时才能阻塞。

### 3.4 项目阶段边界混杂

旧 9C 将 PyTorch 教学重构发布为 v0.1，但“第一阶段总验收”又要求先完成 NumPy 推理。新文件明确拆分：

- PyTorch 工程闭环：2–9B；
- GitHub v0.1：9C；
- NumPy 推理扩展：10；
- 纯标准库可选扩展：11；
- 隐私准备：12。

## 4. 事实核对中修正的两处错误

1. 中文译文实际路径是 `背景/01 基于时序卷积网络的单通道EEG自动睡眠分期特征融合模型_中文译文.docx`；旧文件在“基于时序卷积网络的”后误多写了 `01`。
2. test split 的 `18,036` 是处理后的 30 秒 epoch 总数；`17,800` 是按每条记录构造完整 `T=50` 序列、分别丢弃尾部后的评估位置数。新文件并列表述，避免继续混称。

## 7. 尚未替用户决定的实验语义

> 后续状态更新（2026-07-20）：用户在核对论文与源代码证据后，已确认采用紧凑序列作为 9B 基线；当前权威规则见根目录 `REPRODUCTION_PLAN.md`，证据见 `reproduction_artifacts/milestone_09b/sequence_semantics_audit.md`。以下文字保留当时文档优化刚完成时的决策背景。

预处理会删除记录内部无效 epoch 并紧凑保存。当前“同一 record 内不跨边界”的序列规则仍可能跨过原始时间轴空洞。

文档重构没有修改这一行为，也没有替用户选择策略。全量缓存或长训练前需明确选择：

- 保持紧凑序列以兼容当前工程，并诚实记录限制；或
- 重建 gap-aware manifest，禁止序列跨过原始时间空洞。

在作出决定前，只允许继续当前函数实现和合成数据自测，不启动全量缓存或长训练。
