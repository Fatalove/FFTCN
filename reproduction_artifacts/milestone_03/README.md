# 里程碑 3：预处理与受试者级划分

## 代码变更说明

本阶段新增 `data/sleep_edf_preprocessor.py` 和对应测试，不修改原仓库模型核心。

| 位置 | 为什么新增 | 设计理由 | 实验语义影响 | 验证方式 |
|---|---|---|---|---|
| `preprocess_record` | 原仓库没有 Sleep-EDF 标签字符串映射接口 | EEG 和标签始终使用同一 mask；映射、删除、裁剪顺序显式固定 | S3/S4 合并为 N3，Movement/Unknown 删除，样本数改变 | 合成索引信号检查同步性；SC4001 参考计数 |
| `split_subjects` | 原 Loader 按文件切分，会泄漏同一受试者的另一晚 | 先按 subject_id 去重，再用局部固定随机源切为 62/8/8 | 正式训练/验证/测试集合与原仓库文件级切分不同 | 集合交集、并集和重复运行测试 |
| `save_processed_record` | 原 Loader 要求 `x/y` NPZ | 保持 `float32 [N,1,3000]` 与 `int64 [N]`，不改 Loader | 只改变存储边界，不改变张量数值 | 保存后重新加载逐元素比较 |

可迁移经验：预处理最危险的错误不是“标签值算错”，而是 EEG 与标签执行了不同的删除索引。测试使用每个时段都不同的索引信号，可以直接发现错位。

## 固定决策

- 映射：W→0、N1→1、N2→2、S3/S4→3、REM→4；
- 删除：Movement time、Sleep stage ?；
- 裁剪：有效标签删除后，首末非 W 外侧最多各保留 60 个 W；
- 划分：固定 seed=42，78 名受试者划为 train=62、validation=8、test=8；
- 保存：每条记录一个 `record_id.npz`，只含 `x` 与 `y`。

## 关于无效时段造成的序列间断

为了对齐原仓库，本阶段删除无效时段后将剩余时段紧凑排列。全集中有 49 条记录的物理裁剪窗口内部含无效标注，共 298 段；紧凑排列可能让无效区间两侧在数组中相邻。

这是已知实验假设，不应被描述为严格连续的生理时间序列。后续构造 TCN 序列时需要决定是否记录原始 epoch index 并阻止跨间断组窗；若改变仓库行为，必须单独记录和比较。

## 全量构建脚本说明

核心测试通过后使用 `scripts/build_sleep_edf_processed.py` 逐条构建正式数据。脚本不修改用户练习函数，只负责编排：读取记录、调用预处理、按受试者 split 保存、累计统计并写 JSON 摘要。

选择 `train/validation/test` 子目录而不是把 153 个 NPZ 放进同一目录，是为了让受试者级划分成为磁盘结构的一部分，避免后续误用原 Loader 的文件级比例切分。大型 NPZ 被 `.gitignore` 排除，生成方法和小型统计摘要保留在版本管理范围内。
