# 里程碑 9B：Sleep-EDF 序列空洞语义审计

## 结论

里程碑 9B 采用论文和原仓库兼容的紧凑序列：删除 Movement/Unknown 后，保留同一记录内剩余 epoch 的数组顺序；按每条记录分别截断并构造非重叠 `T=50` 序列。序列不得跨 `record_id`，但不为记录内部被删除的无效 epoch 建立额外边界。

gap-aware manifest 不替换当前基线，只作为 9B 完成后的可选对照实验。

## 论文证据

论文的数据处理描述包括：S3/S4 合并为 N3，记录首尾最多保留 30 分钟 W，并删除 Movement/Unknown。模型接收 `T_N` 个 30 秒 epoch，实验取 `T_N=50`。Table I 给出的 Sleep-EDF-153 总数和五类计数为：

```text
total = 191,800
W/N1/N2/N3/REM = 62,307 / 21,508 / 69,113 / 13,039 / 25,833
```

论文没有显式讨论删除内部无效 epoch 后是否保留时间空洞。

## 源代码证据

1. `README.md` 说明合并 S3/S4、裁剪首尾 W、删除 Movement/Unknown。
2. `data/preprocessor.py::cut()` 只依据非 W 标签裁剪记录，不输出原始 epoch 索引或空洞元数据。
3. `data/loader.py::Sleep_Data` 读取清洗后的 `x/y`，计算 `floor(N / seq_len)`，截断尾部后直接 `reshape`；没有时间戳或 gap-aware 接口。
4. `scripts/run_source_reproduction.py::SourceSplitDataset` 在直接复现中读取里程碑 3 的紧凑 NPZ，并保留相同的截断与 `reshape` 语义。因此直接复现成功证明紧凑序列工程链路可训练，不代表源仓库另有空洞处理模块。

## 全量数值核对

| 口径 | 有效位置 | W / N1 / N2 / N3 / REM |
|---|---:|---|
| 里程碑 3 清洗后 | 195,479 | 65,951 / 21,522 / 69,132 / 13,039 / 25,835 |
| 每记录按 `T=50` 截断 | 191,800 | 62,307 / 21,508 / 69,113 / 13,039 / 25,833 |
| 论文 Table I | 191,800 | 62,307 / 21,508 / 69,113 / 13,039 / 25,833 |
| gap-aware 分段后再按 `T=50` 截断 | 188,650 | 62,191 / 21,244 / 67,842 / 12,579 / 24,794 |

紧凑序列的总数和五类计数与论文逐项完全一致，这是采用该基线的主要证据。

## 已知限制

- 以原始物理裁剪窗口统计，49 条记录中包含 298 个无效 epoch。
- 按当前紧凑预处理最终保留范围统计，48 条记录跨越共 302 个被删除的内部无效 epoch。两个数字口径不同，并不矛盾。
- 全数据共有 3,836 个非重叠 `T=50` 序列，其中 110 个至少跨越一个内部空洞，占约 `2.87%`。
- gap-aware 分段会减少 63 个序列、3,150 个有效位置，并改变类别分布，因此不能在论文兼容基线中静默替换。

最终实验报告必须披露上述限制；后续如果实施 gap-aware 对照，必须使用独立配置、独立缓存和独立结果表，不能与基线指标混称。
