7. 任何代码变更都必须在对应操作手册或里程碑产物中说明修改位置、原问题、修改理由、实验语义影响和验证方法；不要求逐行解释，但禁止只记录“修复”或“优化”。
8. 从里程碑 3 起，每个用户编程练习必须同步提供 `learning_guides/milestone_XX/` ACM 式中文教程和独立参考答案；正式练习文件和参考实现中的说明性文本、docstring、注释默认使用中文，函数名、变量名和 API 契约保持代码规范。按“读题与题意分析 → 必要 Python/NumPy 基础 → 手工推演 → 带块级/行级注释的最小准确代码 → 聚焦测试与错误解释”组织。面向新手的核心代码注释要尽量细，优先解释每一行或每个紧密代码片段的作用、形状变化和为什么这样写。主答案只保留算法正确性必需检查，额外防御性代码移入“工程加固（选读）”；参考代码不得自动覆盖或被正式实现导入。新里程碑改为“等待用户练习”前，Codex 必须逐项通过 `learning_guides/COMMENT_QUALITY_GATE.md`，并把人工注释审读结论写入该里程碑验证摘要；语法测试、行为测试和注释行数均不得替代这项审读。

## 2. 总目标

使用 Sleep-EDF-153 数据集完成 FFTCN 的单数据集工程复现，并通过逐步实践掌握：

- 睡眠 EEG 数据与睡眠阶段标签；
- EDF 数据读取、预处理和受试者级数据划分；
- Morlet 连续小波变换及其数值实现；
- 1D-CNN、2D-CNN、非因果 TCN 和残差连接；
- 特征融合和两步训练策略；
- 分类指标与工程评估；
- PyTorch 模型到 NumPy 单文件推理的等价转换；
- 进一步摆脱 NumPy、手写基础算子的实现方法；
- 面向患者 EEG 数据保护的 HE/TEE 改造边界。

本项目当前复现目标是仓库代码版 FFTCN：

- 1D-CNN 时域特征：256 维；
- 2D-CNN 时频特征：216 维；
- 融合特征：472 维；
- TCN 输出通道：128；
- 睡眠阶段类别数：5。

## 3. 非目标

当前阶段不包含：

- SHHS-1 和 ISRUC-S1 数据集实验；
- 论文三数据集的完整复现；
- Sleep-EDF-153 十折交叉验证；
- 对论文精度、宏平均 F1 或 kappa 指标作严格复现承诺；当前“原仓库结果级直接复现预检”采用固定 `8:1:1` 工程级划分，只用于判断代码链路和结果量级是否大致可信；
- 第一阶段立即放弃 PyTorch 或 NumPy；
- 仅通过代码合并、混淆或加密源码来宣称患者数据受到保护；
- 在完成明文推理等价验证前直接实现同态加密模型。

最终成果只能表述为“FFTCN 在 Sleep-EDF-153 上的单数据集工程复现”。

## 6. 论文版与仓库版差异

| 项目 | 论文版 | 当前仓库版 | 本项目选择 |
|---|---:|---:|---|
| 压缩小波图 | `200×30` | `30×60` | `30×60` |
| 1D-CNN Conv 2-4 卷积核 | 7 | 8 | 8 |
| 时域特征 | 384 | 256 | 256 |
| 2D-CNN 卷积池化块 | 5 | 实际启用 4 | 4 |
| 小波特征 | 432 | 216 | 216 |
| 融合特征 | 816 | 472 | 472 |
| 微调轮数 | 100 | 训练入口为 50 | 首次工程跑通使用可配置轮数 |

论文将 CWT 压缩描述为窗口长度 `m=15`，即 `3000×30 -> 200×30`；但 GitHub 仓库实际训练代码使用 `waveshape=(30, 60)`，即 `3000×30 -> 60×30` 后按代码张量约定保存为 `[1,30,60]`。里程碑 4 和后续模型对齐均以仓库版为准。

论文将 TCN 扩张因子描述为 `0、1、2、4`，而仓库代码按 `2**i` 构造 PyTorch dilation，实际为 `1、2、4、8`。本项目实现仓库行为，并在讲解时区分论文的“间隔”表述和框架的 dilation 参数。

## 7. 固定数据与模型契约

### 7.1 标签

| 睡眠阶段 | 整数标签 |
|---|---:|
| W | 0 |
| N1 | 1 |
| N2 | 2 |
| N3 | 3 |
| REM | 4 |

S3 和 S4 合并为 N3；Movement、Unknown 和无法映射的标签必须删除。

### 7.2 关键形状

| 对象 | 形状 |
|---|---|
| 单个 30 秒 EEG 时段 | `[1, 3000]` |
| 连续原始 EEG 序列 | `[T, 1, 3000]` |
| 单个压缩小波图 | `[1, 30, 60]` |
| 连续小波图序列 | `[T, 1, 30, 60]` |
| 时域特征 | `[T, 256]` |
| 小波特征 | `[T, 216]` |
| 融合特征 | `[T, 472]` |
| TCN 表征 | `[T, 128]` |
| 分类 logits | `[T, 5]` |

完整 FFTCN 默认使用 `T=50`。预训练两个特征分支时使用单时段输入，即 `T=1` 的等价形式。

### 7.3 NumPy 单文件推理接口

```powershell
python fftcn_numpy_infer.py `
  --input eeg.npy `
  --weights model.npz `
  --output predictions.npz
```

输入：

- `eeg.npy`：`float32`，形状为 `[50,3000]` 或 `[B,50,3000]`；
- `model.npz`：导出的推理权重和模型元数据。

输出 `predictions.npz` 至少包含：

- `logits`：`[...,50,5]`；
- `probabilities`：`[...,50,5]`；
- `labels`：`[...,50]`。

单文件推理必须在脚本内部完成 CWT、两条 CNN 分支、特征融合、TCN 和分类，不得导入仓库中的 `data` 或 `models` 模块。

### 里程碑 1：环境与结构认知

- 能解释论文版 816 维与仓库版 472 维差异的来源。

Codex 职责：

- 解释环境文件中每个核心依赖的用途；
- 引导用户逐层手算 1D-CNN 和 2D-CNN 的输出尺寸；
- 提供环境检查脚本和形状计算测试，但不开始模型实现。

用户练习：

- 创建独立 `fftcn` 环境；
- 记录 Python、PyTorch、CUDA、NumPy 和 SciPy 版本；

- 把 CUDA Toolkit、显卡驱动和 PyTorch CUDA runtime 混为一谈；
- 把论文结构误认为仓库实际执行结构；

- 环境诊断命令成功；

- 形状测试无需训练即可通过。

### 里程碑 1B：原仓库结果级直接复现预检

定位：

- 里程碑 1A 是代码导览，只证明主链可跑通；
- 里程碑 1B 才称为“源代码直接复现”，目标是在不改模型核心算法的前提下，尽量用原仓库训练/评估链路跑出 Sleep-EDF-153 上的正式指标；
- 该里程碑是继续投入后续从零复现前的可信度关卡。如果结果与论文差距过大，且不能由数据集版本、划分方式、训练轮数、随机种子或仓库/论文参数差异合理解释，则暂停后续复现。

知识目标：

- 明确原仓库从 `.npz` 数据、`Sleep_Loader`、两分支预训练、融合微调到指标导出的完整运行关系；
- 明确哪些修改只是数据/配置适配，哪些修改会改变实验语义；
- 学会用测试集指标、混淆矩阵、日志、配置和 checkpoint 共同判断一次实验是否可复核。

Codex 职责：

- 先解析原仓库实际训练入口、数据入口、模型构造、checkpoint 加载和指标导出位置；
- 只在必要时修改数据接口、路径配置、设备选择、指标除零和保存加载方式，不修改 1D-CNN、2D-CNN、TCN、损失函数和训练阶段语义；
- 每个修改点在操作手册中按“文件作用 → 输入数据 → 处理路径/函数 → 输出数据 → 原代码行号 → 修改代码行号 → 为什么改 → 如何验证”记录；
- 运行验证命令时，除下载数据或准备全量缓存外，单次代码正确性验证默认不超过 1 分钟，优先使用 `--dry-run`、小 batch、1 个 epoch 或 `py_compile`/单元测试确认修改正确；
- 完成后交付 `reproduction_artifacts/source_reproduction/OPERATION_MANUAL.md`，先写逐步操作，再写总体代码框架图、注意事项和结果对照表模板。

用户练习：

- 按操作手册逐步执行数据准备、两分支预训练、融合微调和测试评估；
- 将最终测试集 ACC、宏 F1、kappa、各类 F1、混淆矩阵、训练轮数、随机种子、数据划分和 checkpoint 路径反馈给 Codex；
- 由 Codex 根据用户反馈与论文指标对照，给出“可信 / 存疑但可继续 / 不可信应放弃”的判断。

代码修改记录规则：

- 小范围修改采用以下形式，便于对照学习：

```python
# 原代码：
# data_path = r"D:\BJM\testdata"

# 修改代码：
data_path = args.data_dir
```

- 若原代码块较长，不复制整段旧代码；保留关键旧行注释，并在操作手册中给出完整上下文行号；
- 不允许把大段核心模型代码注释后重写成另一套模型，因为那会失去“直接复现原仓库”的意义；
- 如果某个修改会改变实验语义，必须单独标为“影响论文可比性”，并说明是否仍能用于可信度判断。

建议操作顺序：

1. 读取 `models/raw/trainer.py`、`models/wavelet/trainer.py`、`models/merge/trainer.py`，确认三阶段训练入口和原始硬编码路径；
2. 读取 `data/loader.py`，确认原仓库 `.npz` 输入契约、`seq_len=1/50` 重排方式和 CWT 触发位置；
3. 读取 `models/raw/network.py`、`models/wavelet/network.py`、`models/merge/network.py`、`models/base/tcn.py`，确认模型结构未被修改；
4. 读取 `models/base/utils.py`，确认 ACC、F1、kappa 和混淆矩阵计算方式，必要时只修复零分母语义；
5. 新增或修改一个直接复现入口脚本，把 Sleep-EDF-153 预处理结果接入原仓库训练链路；
6. 用极小轮数验证路径、设备、checkpoint、指标文件都能生成；
7. 用户再按手册启动较长训练，得到正式指标后反馈。

通过条件：

- 操作手册清楚说明每一步操作哪个文件、为什么操作、输入输出形状如何变化；
- 所有必要代码修改都有原代码注释、修改代码、行号、理由和验证方法；
